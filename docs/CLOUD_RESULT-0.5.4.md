# 节点二：融合姿态、深度网格与三轴惯性联动（0.5.4 / 13）

继承节点一 0.5.3（d8c84bf）的锁屏可见窗口适配、肩背留量和尺寸滑杆，在同一个 feature/cloud-framing-response 分支继续。四张原图、人物纹理、服装、16384 个三角形和原接触权重均保留。

## 已实现

### 观看方向

SensorFeed 优先游戏旋转向量，缺失时使用普通旋转向量，再缺失时继续用已有重力倾斜。相对四元数用 conjugate(baseline) × current 计算，在进入时的手机局部坐标系内取观看方向；屏幕旋转时重设基线并映射坐标轴。抬手机进入锁屏时的任意持握姿态均可成为中性姿态。

这解决了手机绕竖直轴转动、重力几乎不变时无法保持对应视角的问题。姿态决定观看方向，角加速度与线性加速度独立激励惯性。姿态停更500ms后回退重力；熄屏/不可见时停传感器并重取基线。没有自己对原始陀螺仪无限积分。

游戏旋转向量仍允许长期航向漂移；本轮不承诺长时间无漂移、磁干扰下绝对朝向或360度姿态观察。设备不支持融合姿态时仍可使用原有重力路线。

### 人物空间结构

新增可编辑 structure.mjs。它以主图手工拟合头颈、肩、躯干、胸部与近侧手臂的深度代理场，并从现有网格导出 character_depth.bin（每顶点一个 float32 深度，196608 字节）。侧/背图仅辅助理解体块，姿态不配准，不宣称由它们完成三维重建。

共享 GLSL 将深度表面绕支撑轴作有限偏航/俯仰和透视投影，再减去中性投影，以保证零姿态保持原图。投影输入上限约偏航±8.0°、俯仰±4.0°；浅深度区域平滑减权，位移软限幅，防止接触区挤压/翻折。深度场、相机距离和投影常量的 CPU 参考由实际 GLES 检查点核对。

纸张、手和坐姿支撑继续使用原接触权重，前景纸张不再单独漂移。远背景与人物有不同视差。应用和网页提供「立体观察 / 仅回弹」对照开关，设置持久化。默认上下位置下移屏高10%，新增0～20%持久化滑杆；用顶部渐隐衔接原图被裁断的发顶，避免直接下移出现硬边。它与人物大小一起用来校正OEM额外裁剪。首次从旧版升级时，迁移旧近景选择到新的舒展构图；用户之后的选择会保留。

### 三维惯性

在已有局部 X/Y 回弹之外加入 Z 深度弹簧，由真实 TYPE_LINEAR_ACCELERATION 的 az 激励。前后推拉可产生向深度方向的滞后与回弹，不会假造横向摇动。局部 X/Y/Z 位移在材质坐标内计算，再按当前观看角度一起投影；转向后惯性方向与深度变化由同一投影处理。发梢继续有独立的双轴延迟。

这仍是一个连续表面的深度代理和局部形变；未完成封闭人体网格、真实体积守恒软体或自遮挡重建。大角度新露出的脸侧、耳后和背部纹理需要另行补齐，不能靠这四张姿势不同的图切换代替。

## 验证结果

- Android SDK34 / JDK17 / Gradle8.7 release 构建成功。版本0.5.4/13，云端产物未签名，正式包须由 dsh 沿用现有密钥签名。
- 既有52项 RenderLoop/EglCore 主机生命周期检查通过。
- 生产 Java 与网页 JS 的回弹轨迹数值对齐，包含新增深度弹簧。合成前后输入的 Z 峰值约1.0789 source px，停止后收敛；静态保持观看方向不持续摇动。
- 检查融合姿态的任意进入基线、纯偏航、q/-q 等价、横屏映射、错误/乱序事件、停更回退及重置。没有手机、没有传感器实录。
- 全网格25组角度组合：没有翻折，三角形面积比约0.469～1.512；12组附加强三轴惯性组合约0.222～2.148，没有翻折，完全固定的接触顶点位移为0。压力测试不等于所有极端手机动作均已视觉验收。
- 桌面 Mesa EGL 使用生产顶点着色器检查180个无运动/有三轴运动的实际栅格点，和CPU参考差异最大约0.674像素。使用同一套生产片元/顶点着色器绘制预览。
- 原13资产/4对副本哈希、接触点、共享着色器、深度导出一致性检查通过。
- 17秒H.264预览：前2秒为相同25%居中系统裁剪的构图模拟，其后15秒由50Hz合成四元数/陀螺仪输入经过真实 Java MotionInput/Attitude/Physics（120Hz）驱动，20fps离屏GLES出图。左右分别为仅惯性和加入深度观看。它不是手机录屏。

可复现检查：

```sh
node android-app/tools/export_mesh.mjs --check
python3 scripts/verify_assets.py
python3 tests/run_lifecycle.py
python3 tests/run_response.py
node tests/structure-regression.mjs
python3 tests/render_gles.py

```

后3项需要 Linux Mesa EGL、Pillow；视频另需 ffmpeg 与 DejaVu 字体。网页未在真实浏览器/手机做交互验收；云端未测耗电、温升、移动GPU性能或 OEM 锁屏裁剪。

## 给 dsh 的两个节点

1. 如需分开判断，先取 d8c84bf（0.5.3/12），签名并测试锁屏背部与平滑惯性。
2. 再取本分支最新提交（0.5.4/13），沿用原签名构建。先用默认90%人物大小、上下位置10%；背部仍被系统裁剪则向左调小，头部被裁则把上下位置向右下移。不要换签名或要求卸载现用版本。
3. 慢速水平转手机并保持，确认观看方向跟随、保持后回弹停止；绕屏幕平面轻倾和前后倾也分别检查。快速反向后应衰减，前后推拉应有轻微深度响应。切到仅回弹作对照。
4. 检查脸/眼镜不被局部发梢拉动，手不离图纸，背部边缘没有背景残影；反复熄屏唤醒。
5. 如果锁屏仍异常，回传实际安装版本、系统 Surface/visible/offset/zoom 日志与不含通知的裁剪反馈。不要以应用预览或 FIRST_SWAP_OK 代替真实锁屏画面。

## 后续继续方向

先以手机反馈校准可见窗口、人物大小、运动方向和阻尼；之后逐步分离头颈/躯干刚性结构、建立明确遮挡边界与补绘区域，再扩展可观察范围。当前深度代理可作为继续开发的数据接口，不能据此宣布终极目标已完成。
