## 实现

原先整片手臂受平滑深度场与局部惯性权重影响，即使手掌固定，肩至肘、肘至腕仍会伸缩，局部软组织也有少量影响扩散到手臂。本轮增加可编辑armSupport：肩(815,575)、肘(815,1010)、腕(350,1175)，上臂/前臂核心半径48/42，外缘36像素平滑融合。

- 用现有观看投影和身体惯性确定肩部位置，不把软组织/发梢弹性作为肩部输入。
- 两段逆运动学保持原图投影中的肩肘/肘腕长度，选择与原图同侧的弯肘解，腕部维持原纸张接触位置。当前限定输入下始终可达。
- 上臂、前臂各用形状保持变换；肘处按连续权重融合，外缘接回原深度表面。完全固定的手、纸张和坐姿约束仍最终生效。
- 手臂核心不再随局部软组织弹簧伸缩，软组织区域自身仍有原有回弹。头部/发梢结构与传感器响应保留。
- 修改了structure.mjs的CPU参考及共享scene.vert，导出同步到Android；没有修改Java/JS弹簧动力学。阴影、纹理与真实隐藏表面未重建。

这是一种主图专用的支撑近似，不能把其它参考图姿势直接套入。除核心区外，融合带仍允许少量形变；未承诺全手臂逐像素刚性。

### 额外极限扫描发现的继承问题

将所有弹簧同时设为硬限位（身体±6、软组织XY±11.9/Z±10.2、发梢X±21/Y±10.5，再乘1.45构图增益）进行24组组合扫描，**全网格没有通过**：凌晨基线和当前都在发梢末端约(246.05,486.44)出现同一翻折，最小面积比-0.53783。不能把常规扫描通过写成所有极限动作均通过。

本轮支撑区域在该极限扫描中的最小面积比0.26824，仍为正；基线0.77926。本轮支撑使融合带应变增加，这是固定骨段/腕部约束的代价，仍需真机视觉评估。没有通过改阈值隐藏翻折。validation/arm-limit-scan.json明确保留allMeshHardLimitPassed=false，脚本只断言支撑区未翻折、既有全局最差值未恶化。

该极限是合成同时硬限位，不是已观测到的手机输入；但属于已知渲染稳定性缺口，下一轮应优先处理发梢权重末端或局部形变安全边界，再考虑扩大角度。
