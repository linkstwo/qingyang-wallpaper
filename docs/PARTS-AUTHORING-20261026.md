# 轻量部件调整工具：首个可操作结果

本轮遵循用户最新方向：保留现有Java/JS/GLES壁纸，使用轻量GitHub算法帮助素材调整；不安装Blender、不换引擎、不下载模型或图片。用户恢复AI桥协作，豆包负责明确的小修与整理，Codex负责核心实现和验收。旧“云端不查桥”仅为历史边界。

## 实际交付

页面：character-prototype/preview/parts-fit.html。使用原有阅读图、侧面图、背面图，可选手臂/肩部/躯干，拖动三个控制点实时调整局部，以外区域保持原图；可调强度、按住原图对照、重置、保存恢复及JSON导入导出。源文件只读，草稿绑定完整SHA256与尺寸，错源数据拒绝。此页是素材制作工具，不是连续侧背已完成，也没有改变手机壁纸的正式资产或Q弹求解器。

核心参考Jarvis73/Moving-Least-Squares（MIT）的MLS相似变形算法。原Python实现已在本机试运行，但输出整数采样坐标，基础对照出现1像素量化误差。因此本页使用浮点JavaScript实现，在浏览器操作而非运行Python图片重采样；许可证保留在preview/third-party/MLS-LICENSE.txt。新增代码不依赖npm包、模型或CDN。GPU一次绘制整个局部网格，避免Canvas2D逐三角形裁剪产生的细缝。

### 有限角度与图像语义复核

90°/180°仅为诊断极端，不是增加360°需求。另实际检查+20°/-20°：纸张出现长条分离与三角空隙，已有有限角度纸面接缝仍未解决。新增validation/side-trial-small-angle-browser.jpg。不能仅以极端失败否定有限视角，也不能忽略有限视角自身的缺陷。

逐像素查看主图/侧图后，主图近臂向下垂、侧图近臂向前弯曲；全图镜像不能把二者当成同姿态表面。后续按肩带/肩颈/躯干分别建立候选对应，手臂独立处理。豆包2003领取的是可见位置整理，Codex负责语义和几何对应取舍，不允许用不可见点补造校准事实。

新增强度反例在真实界面通过：导入gain=0的镜像目标控制点（此时原图有效），滑块试拉100%触发翻折，实际滑块和JSON都退回0，提示保留上一步。此反例截图捕获失败，保留DOM与数据验证结论，不虚报截图成功。
